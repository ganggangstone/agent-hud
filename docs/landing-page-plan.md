## 3. 시각 언어 (server.py PAGE에서 그대로 가져옴)

색 변수는 `server.py:902-912`를 **그대로 복사**한다. 사본이 갈라지지 않게, 랜딩 페이지 CSS 맨 위에 "출처: server.py `:root`" 주석을 단다.

라이트:
```
--bg:#f5f6f8  --panel:#ffffff  --border:#e5e7eb  --text:#1d2129  --dim:#8a919e
--accent:#3182f6  --on:#00a870  --off:#5f6673
--accent-tint:#eaf2ff  --on-tint:#e3f9ef  --off-tint:#eef0f2
--shadow:0 1px 2px rgba(0,0,0,.04),0 1px 6px rgba(0,0,0,.03)
```
다크(`:root[data-theme="dark"]`):
```
--bg:#0d1117  --panel:#161b22  --border:#262c36  --text:#e6edf3  --dim:#8b949e
--accent:#58a6ff  --on:#56d364  --off:#8b949e
```

- **폰트: IBM Plex 아니다.** 시스템 폰트 스택이다 — `-apple-system, "SF Pro Text", "Pretendard", Inter, sans-serif`, 본문 `14px/1.5`. 코드·경로·태그는 `ui-monospace, "SF Mono", Menlo, monospace`. 웹폰트를 새로 들이지 않는다(제품 화면과 달라지고, 의존성이 는다).
- 제목: `h1` 23px / weight 800 / `letter-spacing:-.02em`. 랜딩 히어로는 더 커도 되지만 같은 weight·letter-spacing을 유지한다. 소제목은 제품의 `#h1sub` 스타일(10px, `letter-spacing:.14em`, uppercase, 모노) 재사용 — 단 한국어일 때는 `letter-spacing:0`, non-uppercase(제품이 `#h1sub:lang(ko)`로 이미 그렇게 한다).
- 모양: 카드 `border-radius:8px` + 1px border + `--shadow`, 알약 `border-radius:999px`, 반응형 분기점 `640px`(제품과 동일).
- **다크/라이트 둘 다 지원한다.** 제품 기본은 다크이므로 랜딩도 다크를 기본으로 두고, `☀/☾` 토글을 제품과 같은 모양(1px border, 10px radius, 11px/700)으로 헤더에 둔다. 선택은 `localStorage`, 미선택 시 `prefers-color-scheme`.
- 이미지: `docs/images/banner.svg`, `skills.png`, `groups.png`, `instructions.png`(+ `-ko` 판본). 언어 토글에 따라 `src`를 바꾼다. **새 스크린샷이 필요하면 `sanitized-demo-screenshots` 스킬로 가짜 데이터에서만 찍는다.**

## 4. 카피 초안

문체: 줄표 금지, "~아니라 ~입니다" 금지, 조사 붙는 자리에 영문 고유명사 두지 않기, 한국어 어순은 `스킬 60개`.

**히어로 (한국어)**
> 이 프로젝트가 스킬 몇 개를 로드하는지 보여준다.
> 함께 쓰는 플러그인과 스킬을 그룹으로 묶어 프로젝트마다 다르게 적용한다.

**히어로 (영어)**
> See how many skills this project loads.
> Save the plugins and skills you use together as a group, and apply a different group to each project.

**문제 제기**
> 코딩 에이전트는 세션을 시작할 때 설치된 스킬마다 이름과 설명을 모델 입력에 넣는다. 본문은 그 스킬을 쓸 때만 읽지만, 이름과 설명은 그 세션에서 쓰지 않는 스킬까지 전부 들어간다.
> 플러그인을 끄는 기본 명령은 사용자 전역 설정에 기록한다. 한 프로젝트에서 끄면 다른 프로젝트에서도 꺼진다.

**숫자 (실측 범위를 넘지 않는 표현)**
> 만든 사람의 컴퓨터에는 플러그인 3개로 스킬 60개가 설치되어 있었다.
> 그 스킬들의 이름과 설명을 합치면 18,938자였고, 세션마다 5,000~9,000토큰이었다.
> Agent Skills 명세는 스킬 하나의 이름과 설명을 약 100토큰으로 본다.

숫자 타일은 `60 스킬 / 18,938자 / 5,000~9,000토큰 per session` 3개. **"X% 절감" 같은 문장은 쓰지 않는다** — 절감량은 어떤 그룹을 쓰느냐에 달렸고 실측한 적이 없다.

**그룹**
> 적용하면 그 그룹의 스킬이 프로젝트 스킬 폴더에 링크되고, 플러그인 값이 그 프로젝트의 설정 파일에 적힌다. 다른 프로젝트의 설정은 바뀌지 않는다. 플러그인 변경은 다음 세션부터 반영된다.

**다른 에이전트 (부차 기능임이 드러나는 톤)**
> 스킬 형식은 공개 표준이라 폴더째 옮겨진다. 체크박스 하나로 같은 스킬을 여섯 에이전트의 스킬 폴더에 링크한다. Cursor는 아직 실측 확인을 못 했다.

**지침 파일 (과장 방지)**
> 프로젝트 트리에서 지침 파일 30종을 찾아 크기와 수정 시각을 보여준다. 내용을 비교하지는 않는다. 색인이고, 대조는 사람이 한다.

**정직함 블록**
> 계정이 필요 없다. 이 컴퓨터의 설정 파일만 읽고 쓴다. 컴퓨터 밖으로 나가는 요청은 새 버전 확인용 GitHub Releases 조회 하나다.

## 5. 기술 방식 제안

**정적 HTML 한 장 + GitHub Pages(저장소 공개 전환 후).**

- 파일: `docs/index.html` 하나. CSS·JS 인라인. `docs/images/`의 스크린샷이 이미 같은 폴더 아래 있어서 상대 경로로 바로 붙는다.
- Pages 설정: Settings → Pages → Source `main` 브랜치 `/docs` 폴더. 액션도 빌드도 없다.
- JS는 세 가지뿐: 테마 토글, 언어 토글(`data-en`/`data-ko` 속성 또는 두 `<section>`을 `hidden`으로 스왑), 스크린샷 `src` 스왑. `localStorage` 저장. 30줄 안쪽.
- **쓰지 않을 것**: 정적 사이트 생성기(Astro/Next/Hugo), Tailwind, 웹폰트, 애널리틱스, 빌드 단계. 이 저장소의 1번 결정("단일 파일 + 표준 라이브러리, 설치 마찰 없음")과 같은 이유로 랜딩도 빌드 없이 둔다.
- 검사: 이 저장소의 기존 방식대로 `tests/test_landing.py` 하나 — `node --check`로 인라인 `<script>` 파싱(제품에서 실제로 사고가 난 지점), 참조하는 이미지가 전부 존재하는지, en/ko 텍스트 쌍이 짝이 맞는지. 추가한 뒤 **일부러 깨뜨려 실패하는지 확인**한다.
- README를 그대로 Pages 테마로 띄우는 방식은 기각: Jekyll 테마 색이 제품과 완전히 달라서 "같은 제품처럼 보여야 한다"는 요구를 못 맞춘다.

## 7. 레이아웃 결정 (2026-09-22, UX/SEO 기준으로 재확인)

**좌우 2단(영-한 나란히) 구조는 기각.** 처음엔 "제품과 이질감" 이유를 들었으나, 사용자가 그 근거는 과하다고 지적 — UX/SEO만으로 다시 판단:

- **SEO는 토글이든 2단이든 차이가 거의 없다.** 둘 다 두 언어 텍스트가 최초 HTML에 그대로 있다(토글은 CSS `display:none`으로 한쪽을 가릴 뿐 JS가 나중에 주입하는 게 아님). 구글은 `display:none` 텍스트도 인덱싱한다.
- **UX는 토글이 낫다.** 2단은 한 언어만 읽는 사람에게 화면 절반이 낭비되고, 언어별 문장 길이가 달라 두 칸 높이가 안 맞아 빈 공간이 생긴다. 2단이 유리한 경우(두 언어 대조 검수)는 랜딩 방문자의 용도가 아니다.

**결정: 제품과 동일한 토글 방식**(헤더의 EN/한국어 pill, 누르면 전체 섹션 스왑).

**진짜 SEO 레버는 레이아웃이 아니라 URL 구조다.** 한 페이지에 두 언어를 다 넣고 토글하면 구글이 이 페이지의 언어를 판단하기 애매해져 검색 노출이 떨어진다. `docs/index.html`(영어)과 `docs/ko/index.html`(한국어)로 **분리하고 `hreflang` alternate 태그로 서로 연결**하는 쪽이 실제 SEO 효과가 크다. 정적 파일 하나 더 두는 정도라 빌드 없음 원칙에서 벗어나지 않는다. → 8번 큐에 반영.
