플러그인 & 스킬 탭. 맨 위 숫자는 사이드바에서 고른 프로젝트 기준이다.

프로젝트마다 쓰이는 스킬과 플러그인이 다른데 다 로드하면 비용과 성능 이슈가 있고, 매번 온오프하고 하기 불편해서 만든 거지. 만든 이유

코딩 에이전트는 세션을 시작할 때 설치된 스킬마다 이름과 설명을 모델 입력에 넣는다. 대화 중에 어떤 스킬을 쓸지 고르려면 그 목록이 필요하기 때문이다. 본문은 그 스킬을 실제로 쓸 때만 읽지만, 이름과 설명은 그 세션에서 한 번도 안 쓰는 스킬까지 전부 들어간다.

플러그인을 끄는 기본 명령은 사용자 전역 설정 파일에 기록한다. 이 프로젝트에서 껐는데 모든 프로젝트에서 꺼지니, 프로젝트를 옮길 때마다 다시 켜게 된다.

한 대의 컴퓨터에서 재보니

“특별히 많이 깔아둔 상태가 아니다.”

플러그인 3개가 설치돼 있었다.

흘수선

선 위는 설치만 돼 있고 놀고 있는 것이다. 선 아래가 이번 세션 컨텍스트에 실려 가는 것이다.

Agent Skills 명세는 스킬 하나의 metadata를 약 100토큰으로 본다. 실제 값은 설치된 스킬들의 설명이 얼마나 긴지에 따라 달라진다. 그래서 대시보드는 남의 컴퓨터 숫자 대신 지금 열어둔 프로젝트의 숫자를 보여준다.

없던 단위가 그룹이다

“다른 프로젝트는 그대로다.”

적용 범위

그룹을 적용하면 프로젝트 하나 안에만 쓴다. 다른 프로젝트는 갖고 있던 것을 그대로 갖는다.

함께 쓰는 플러그인과 스킬에 이름을 붙여둔다. 적용하면 그 그룹의 스킬이 프로젝트 스킬 폴더에 링크되고, 그룹의 플러그인은 켜지고 나머지는 꺼지며, 그 내용이 프로젝트의 .claude/settings.local.json에 적힌다.

설정은 세션이 끝나도 남아 있어서 다음 세션도 같은 상태로 시작한다. 플러그인 변경은 다음 세션부터 반영된다.

  1. 그룹을 만들고 플러그인과 스킬을 담는다.
  2. 사이드바에서 프로젝트를 고른다.
  3. 적용한다. 폴더에서 agent-hud apply dev로도 된다.

modes.json

{
  "dev": {
    "plugins": ["mattpocock-skills@mattpocock"],
    "skills": ["diagnosing-bugs"]
  },
  "video": ["video-tools@local"]
}

그룹 탭에서 고쳐도 되고 파일을 직접 고쳐도 된다. 파일을 고치면 다음 갱신 때 반영된다.

남은 탭 두 개

폴더 하나, 링크 둘, 에이전트 여섯

“폴더째 옮겨진다.”

심볼릭 링크

스킬 형식은 공개 표준이다. 에이전트마다 읽는 경로가 다르므로, 대시보드가 스킬 하나를 프로젝트의 스킬 폴더 두 곳에 심볼릭 링크로 건다. 링크 두 개가 에이전트 여섯 개를 덮는다. Cursor와 Copilot은 두 폴더를 다 읽는다.

이 기능은 덤이고, 만든 이유는 위쪽에 있다. 지침 파일은 에이전트마다 따로 두고 대시보드는 목록만 보여준다.

설치

git clone https://github.com/ganggangstone/agent-hud.git
cd agent-hud && ./install.sh

또는 brew install ganggangstone/tap/agent-hud

브라우저가 127.0.0.1:7717에 열리고 launchd 서비스가 계속 띄워둔다. 이 부분은 macOS 전용이고, Linux는 systemd --user 유닛이 server.py를 실행하게 하면 된다. Windows는 아직 지원하지 않는다(#1).
