Agent HUD

Every skill and plugin you
have installed, in one place.
Off for the projects that don't need them.

A dashboard that runs on your own computer. No sign-up, no account.

git clone https://github.com/ganggangstone/agent-hud.git cd agent-hud && ./install.sh or brew install ganggangstone/tap/agent-hud

macOS only, for now

It opens in your browser at 127.0.0.1:7717 and stays running in the background. On Linux you can run server.py yourself, and Windows is not supported yet (#1).

A coding agent reads every installed skill's name and description at the start of a session.
The ones you never use, too.

60 skills · 18,938 characters · 5,000–9,000 tokens every session

These are example numbers, from one machine with three plugins installed — about 100 tokens per skill, going by the Agent Skills standard. Yours will differ with how many skills you have and how long their descriptions run. The dashboard counts your own project for you.

So we built a way to switch off the skills and plugins a project never uses.

A group is just the plugins and skills you use together. Apply one and this project gets exactly those — everything else is switched off. Only the project you picked changes; your other projects stay as they are. Plugin changes take effect the next time you start a session.

{
  "dev": {
    "plugins": ["mattpocock-skills@mattpocock"],
    "skills": ["diagnosing-bugs"]
  },
  "video": ["video-tools@local"]
}

You can edit it in the Groups tab, or in modes.json directly.

A skill you wrote for one agent can work in all six.

The skill format is an open standard. Agents read different paths, so the dashboard symlinks one skill into both — you write it once and never copy it again.

It also finds the instruction files you scattered around.

30 kinds of CLAUDE.md, AGENTS.md, .cursor/rules/ and the rest, with size and modified time. It indexes them; it does not compare them.

Questions that come up.

Why macOS only?

The installer registers a launchd service, and that part is macOS-only. server.py itself has no OS-specific code, so on Linux you can point a systemd --user unit at it instead. Windows is not supported yet (#1).

What does it change on my computer?

Plugin state and skill symlinks, inside the project you applied a group to. Instruction files are only ever listed — it never edits them.

Do my other agents need setting up?

Claude Code registers a project on its own. For one you use only with Cursor, Codex, Gemini CLI or Antigravity, add it with + add a folder in the dashboard; skill badges and group apply then work the same way.

So you can see for yourself what it does, the whole thing is one Python file that runs only on your computer, using nothing but the standard library. Nothing is uploaded and there is no account to make. One request ever leaves the machine: a GitHub Releases check every 12 hours, to see whether a newer version exists.
