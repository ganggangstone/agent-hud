# 결정 기록 (ADR)

이 문서는 **왜 그렇게 정했는지**만 적는다. 무엇을 만드는지와 사용법은 `README.md`에 있다.

결정이 바뀌면 여기 항목을 고치고 바뀐 이유를 한 줄 덧붙인다. 지우지는 않는다 —
"왜 그때 그걸 안 골랐는지"를 잊으면 같은 논의를 처음부터 반복하게 된다.

`결정자` 열은 나중에 이 결정을 뒤집을 때 누구에게 물어야 하는지를 알려준다.
**Claude**로 적힌 항목은 기술적 근거로 정한 것이라 근거가 무너지면 바로 뒤집어도 된다.
**사용자**로 적힌 항목은 취향·제품 방향이라 함부로 뒤집으면 안 된다.

## 1. 무엇으로 만들 것인가 (그릇)

| 대안 | 장점 | 단점 | 판정 |
|---|---|---|---|
| **단일 파이썬 파일 + 표준 라이브러리** ✅ | 설치가 파일 복사 하나, macOS에 파이썬이 이미 있음, 의존성 취약점·버전 충돌 없음 | HTML/CSS/JS가 파이썬 문자열 안에 산다(에디터 지원 없음) | **채택** |
| Flask/FastAPI | 라우팅·템플릿이 편함 | 이 도구가 하는 일은 GET 4개, POST 5개다. 그걸 위해 사용자에게 `pip install`을 시킨다 | 기각 |
| Electron/Tauri 데스크톱 앱 | 창·트레이가 자연스러움 | 상태를 보는 게 전부인 도구에 상주 프로세스와 수십~수백 MB를 쓴다 | 기각 |
| CLI (`agent-hud status`) | 가장 가벼움 | 상태는 **계속 보면서 작업하는 것**이지 한 번 찍어보는 게 아니다. 토글도 불가능 | 기각 |

**결정자: Claude** — "설치 마찰이 낮아야 한다"와 "브라우저에서 상시 띄워둔다"는 두 조건이
나머지를 배제했다. 단점(문자열 안의 HTML)은 실재하지만, 파일 하나로 배포되는 이득이 더 컸다.

## 2. 상태를 어떻게 읽는가

| 대안 | 장점 | 단점 | 판정 |
|---|---|---|---|
| **설정 파일을 직접 읽는다** ✅ | 빠르고, `claude`가 실행 중이 아니어도 되고, 3초마다 불러도 부담이 없음 | Claude Code가 파일 형식을 바꾸면 조용히 깨진다 | **채택** |
| `claude` CLI를 호출해 파싱 | 공식 인터페이스라 형식 변경에 강함 | 프로세스 기동 비용이 폴링마다 붙는다. 출력이 사람용이라 파싱이 더 취약할 수도 있다 | 기각 |

**결정자: Claude** — 폴링이 전제라 프로세스 기동 비용이 결정적이었다.
**대신 형식이 바뀌면 깨진다는 걸 감수한 선택이므로**, 읽기 함수는 전부 `read_json`의
기본값 폴백을 거쳐 "못 읽으면 빈 값"으로 떨어지게 했다. 대시보드가 죽는 것보다 낫다.

## 3. 상태를 어떻게 바꾸는가 ⭐ 비대칭이라 설명이 필요하다

같은 도구인데 쓰기 경로가 둘로 갈린다. 의도된 것이다.

| 대상 | 방법 | 이유 |
|---|---|---|
| 플러그인 on/off | **`claude plugin enable\|disable` CLI 호출** | Claude Code가 `settings.json`의 `enabledPlugins` 말고 다른 것도 함께 손볼 수 있다. 공식 명령이 있는데 파일을 직접 쓰면 그 부수 작업을 빠뜨린다 |
| 스킬 차단/허용 | **프로젝트 `.claude/settings.json`을 직접 쓴다** | `permissions.deny`에 `Skill(플러그인:스킬)` 한 줄을 넣고 빼는 것이 전부이고, **이걸 하는 공식 명령이 없다** |

**결정자: Claude** — 규칙은 "공식 명령이 있으면 그걸 쓰고, 없을 때만 파일을 직접 쓴다"다.
새로운 쓰기 기능을 붙일 때 이 순서를 먼저 확인할 것. 그리고 파일을 직접 쓰는 쪽은
**전역이 아니라 프로젝트 파일에만** 쓴다 — 사용자의 전역 설정을 도구가 건드리지 않는다.

## 4. 화면을 언제 갱신하는가

| 대안 | 장점 | 단점 | 판정 |
|---|---|---|---|
| **3초 폴링** ✅ | 코드가 `setInterval` 한 줄. 서버는 상태가 없고, 탭을 여러 개 열어도 문제없음 | 최대 3초 지연, 아무도 안 보는 동안에도 돈다 | **채택** |
| SSE / WebSocket | 즉시 반영, 유휴 시 조용함 | 연결 상태·재연결·서버측 구독자 관리가 생긴다. 읽는 게 로컬 JSON 몇 개인데 그럴 값어치가 없다 | 기각 |
| 파일 감시(watchdog) | 변경 순간에만 갱신 | 의존성이 생기고(결정 1 위반), 감시할 경로가 프로젝트마다 늘어난다 | 기각 |

**결정자: Claude** — 이 화면에서 3초 지연은 사용자가 느끼지 못한다.
**단, 사용자가 스위치를 누른 직후에는 폴링을 멈추고(`polling = false`) 즉시 다시 읽는다** —
자기가 누른 것이 반영되는 건 기다리면 안 된다.

## 5. 어떻게 상시 실행하는가

| 대안 | 장점 | 단점 | 판정 |
|---|---|---|---|
| **launchd 서비스 + 세션 훅이 프로젝트만 등록** ✅ | 터미널·세션과 무관하게 살아 있고 죽으면 자동 재시작. 포트가 안 바뀜 | macOS 전용 패키징 | **채택** |
| 세션마다 서버 기동 | 설치가 훅 하나로 끝남 | 세션을 열고 닫을 때마다 서버가 뜨고 죽는다. 포트가 흔들리고 브라우저 탭이 계속 새로 열린다 | 기각 |
| 사용자가 수동 실행 | 가장 단순 | 상시 상태판인데 켜는 걸 잊으면 존재 의미가 없다 | 기각 |

**결정자: 사용자** (macOS만 쓰는 환경) — `server.py` 자체엔 OS 종속 코드가 없으므로
리눅스는 `systemd --user`로 같은 구조를 만들 수 있다. 이식성을 위해 코드를 바꿀 필요는 없다.

세션 훅은 **서버를 띄우지 않는다.** 이미 떠 있으면 `/api/register`로 프로젝트 경로만 알리고
빠진다. 이게 없으면 터미널을 열 때마다 서버가 늘어난다.

| 대안 | 장점 | 단점 | 판정 |
|---|---|---|---|
| **버전 확인만, 다운로드는 수동(`git pull`)** ✅ | 구현이 몇 줄. git으로 받는 도구라 업데이트 방법이 이미 있음 | 사용자가 직접 한 단계를 밟아야 함 | **채택** |

## 9. 다른 에이전트(Cursor, Codex 등)도 지원할 것인가

**판정(2026-09-09 뒤집힘): 지원한다. 이름도 `Agent HUD`로 먼저 바꿨다.**
아래 2026-09-08 조사 내용은 그대로 둔다 — 형식이 갈린다는 사실은 여전히 맞고, 그래서
"무엇을 만들지"의 범위를 정하는 근거로 계속 쓰인다.

**뒤집은 이유** — 아래 "뒤집을 조건"이 실측으로 충족됐다:
- 이 기계에 `~/.claude`와 `~/.codex`가 둘 다 있다. 즉 사용자는 이미 멀티에이전트를 쓴다.
- 한 프로젝트(`example-app`)에 지침 파일이 4종 있다: `CLAUDE.md`, `AGENTS.md`,
  `.clinerules`, `.cursor/mcp.json`.
- **그리고 이미 갈라져 있다.** 같은 규칙(dev 서버 포트 고정, ponytail 원칙, 플랫폼별 타깃
  사용자)이 파일마다 있기도 하고 없기도 하다. 이게 원칙 8이 말하는 "사본은 갈라진다"의 실례다.
- 이름을 먼저 바꾸는 것도 이번엔 비용이 0이다 — **아직 push 전이라** 리다이렉트에 기댈
  기존 사용자가 없다. "기능 없이 이름만 바꾸면 없는 기능을 약속한다"는 우려는 유효하므로,
  첫 기능(아래 ①)을 같은 릴리스에 넣는다.

**만들 것**: ①**지침 파일 통합 뷰** — 지금 `collect_instructions`가 `CLAUDE.md`와 agents
디렉터리만 보는 것을 다른 도구의 지침 파일까지 확장하고 **크기·수정시각**을 함께 보여준다.
읽기 전용이라 쓰기 위험이 없고 패널 구조도 그대로다.

> **구현 결과 (2026-09-09)**: 위에 적었던 7종 대신 **29종**으로 만들었다
> (`INSTRUCTION_SOURCES`). Roo Code·Aider·Goose·Junie·Kiro·Continue·Amp·Amazon Q·
> Augment·JetBrains AI·Trae·OpenHands·Crush·Warp·Qwen·Firebase Studio와 Copilot의
> `.github/instructions/`가 추가됐다. 경로는 ruler의 도구별 출력 경로표와 각 도구 문서로
> 대조했다. 디렉터리형 소스는 경로 끝의 `/`로 구분한다.
>
> **그리고 범위를 정정한다.** 위 "뒤집은 이유"는 `example-app`의 실제 드리프트(같은
> 규칙이 `AGENTS.md`와 `.clinerules`에 중복)를 근거로 들었지만, **크기·수정시각으로는 그
> 드리프트가 보이지 않는다.** 지금 만든 것은 드리프트 탐지기가 아니라 **흩어진 지침 파일을
> 한 자리에서 여는 색인**이다. 내용 대조는 **하지 않기로 했다(2026-09-09)**: 겹치는 줄을
> 문자열로 비교하면 복붙한 중복은 잡지만 같은 규칙을 다른 문장으로 쓴 경우는 못 잡고,
> 제목·빈 줄에서 오탐이 난다. **못 잡는 게 더 많은 검사는 "표시가 없으니 괜찮다"는
> 잘못된 안심을 준다** — 색인으로 두고 대조는 사람이 하는 편이 정직하다.
>
> 부작용 하나: `/api/state?project=`가 검증되지 않으므로(`server.py`) `/api/content`가
> 허용하는 파일 이름이 2개에서 29개로 넓어졌다. 서버는 `127.0.0.1` 전용이고 CORS 헤더가

`~/.claude.json`·`~/.claude/settings.json` 어디에도 `mcpServers`가 없었다).

**하지 않을 것**: 플러그인 on/off·그룹·스킬 override를 다른 도구로 확장하는 것. 대응 개념이
없다. UI에서 **"이 탭은 Claude Code 전용"**이라고 밝히는 편이 정직하다.

<원래 판정 (2026-09-08)> **지금은 하지 않는다.**

이 도구가 보여주는 것 — 플러그인 on/off, 그룹, 스킬 permission override — 은 전부
**Claude Code에만 있는 개념**이라 다른 도구로 옮길 대상이 없다. 조사로 확인한 것:

- **AGENTS.md**는 30개 이상 도구가 읽는 사실상의 표준이지만 **Claude Code는 읽지 않는다**(CLAUDE.md를 읽는다). 즉 "지침 파일 유무"조차 통일된 신호가 아니다.
- 설정 형식이 갈린다: Claude Code는 JSON, Codex CLI는 **TOML**, Cursor/Windsurf/Cline은 **Markdown 룰 파일**. 공통 파서를 만들 표준이 없다.
- 유일하게 형태가 수렴하는 지점은 **MCP 서버 목록**(`mcpServers` 유사 JSON)인데, 위치는 도구마다 다르다.

**뒤집을 조건**: 하게 된다면 범위를 줄여야 한다 — ①이 프로젝트에 어떤 에이전트의 설정이
있는가 ②MCP 서버 통합 뷰 ③지침 파일 보기 정도. 그때는 `collect_x(ctx) -> dict` 패널을
에이전트별로 추가하는 형태가 되므로 **지금 구조를 바꿀 필요는 없다.**

이름 변경(`Agent HUD` 등)은 그 기능이 실제로 생긴 뒤에 한다.
**기능 없이 이름만 바꾸면 없는 기능을 약속하게 된다.** </원래 판정>

### 나중에 이름을 바꿔도 되는가 (2026-09-08 공식 문서 확인)

[GitHub 공식 문서](https://docs.github.com/en/repositories/creating-and-managing-repositories/renaming-a-repository)
기준으로 **바꿔도 된다.**

- **리다이렉트된다**: 웹 링크, 이슈, 위키, 스타, 팔로워, 그리고 git 조작 —
  *"All `git clone`, `git fetch`, or `git push` operations targeting the previous
  location will continue to function as if made on the new location."*
- **REST API는 301을 돌려준다.** 이 도구의 업데이트 확인이
  `api.github.com/repos/{repo}/releases/latest`를 부르는데 `urllib.request`가 GET의 301을
  따라가므로, 이미 배포된 구버전 설치본도 이름 변경 후 계속 동작한다(실제로 확인했다).
- **리다이렉트 안 되는 것**: GitHub Actions가 참조하는 액션(`repository not found`로 실패),
  GitHub Pages 프로젝트 사이트 URL. 이 저장소는 둘 다 쓰지 않는다.
- **함정**: 이름을 바꾼 뒤 **옛 이름으로 새 저장소를 만들면 리다이렉트가 끊긴다** —
  *"do not reuse the original name of the renamed repository."*
